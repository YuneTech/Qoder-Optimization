# 合并入站 Qoder 包

## 1. 隔离与基线

1. 把包解压到非系统盘带时间戳目录，不在原包旁直接覆盖。
2. 记录包哈希、文件清单和来源；未知第三方包先走 `inspect-untrusted-tool-package`。
3. 找到“本机当前真源”和“上次双方共同基线”。没有共同基线时只做双向差异，不伪装成三方合并。

## 2. 差异三分类

按相对路径和 SHA-256 分成：

- 对方新增：本机无、包内有。
- 双方同路径改动：需要三方读取。
- 对方缺失：本机有、包内无；默认视为能力丢失风险，绝不按包删除。

先列清单，再决定落点；禁止 `cp -r`、整目录覆盖和按 mtime 选赢家。

## 3. 卫生预检

逐文件检查：占位符、对方机器绝对路径、用户名、凭据、内网地址、调试日志、备份文件、零字节、CRLF/LF 约束、会外发数据的代码。命中敏感项只报告位置与类型，不回显内容。

## 4. 判定真实落点

对 `skills/`、`skills-library/`、`scripts/`、`rules/`、`memory/`、`commands/` 分别读取 `realpath`、junction/symlink 和客户端配置根；不要沿用历史拓扑。链接目录只改真源一次，实体双副本按同步机制分别处理。

## 5. Dry-run 与落地

1. 生成逐文件计划：来源、目标、动作、是否已有、备份路径、验证命令和回滚方式。
2. 对每个既有目标先运行 `backup-file.js`；新文件先确认父目录与分层。
3. 单文件定点合并：保留本机独有约束，只吸收对方独有且仍有效的内容。
4. 长文档按标题、锚点和行数做结构断言，防段落粘连或远锚点吞段。
5. 每改一项立即按目标路径重算哈希；不等最后才发现写错副本。

## 6. 三方冲突

- 共同基线 → 本机独有 → 对方独有，三者逐段比较。
- 两侧都改同一语义时以当前现场和更高层规则为准，不用时间戳裁决。
- 对方包缺少本机能力不代表删除授权；先保留并在报告中列为“未回流”。

## 7. 收口

1. 技能有增删改时重建索引并做通用问法、产品问法、无关问法三组路由验收。
2. 跑 `skills-doctor`、`skill-collisions`；涉及规则/hook 再跑全局配置冒烟。
3. 逐文件汇报新增、更新、跳过、冲突和回滚点；未运行的客户端级验证标“未验证”。

## 回滚

只按本轮计划中记录的备份逐文件恢复；恢复前先核对现文件哈希仍等于本轮修改后哈希，有并发变化就停止整文件覆盖，改做三方撤销。
